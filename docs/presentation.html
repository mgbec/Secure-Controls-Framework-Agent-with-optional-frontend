Access model

Three ways in, three auth models

  • IAM / SigV4 — AWS principals and CLI scripts invoke the runtime directly.
  • A2A protocol — other agents call it over JSON-RPC through an API Gateway, authenticated with OAuth2 / OIDC bearer tokens (Cognito or Microsoft Entra ID).
  • Hosted UI — an optional Streamlit web app for humans (currently disabled to cut cost; ready to switch back on).

Same agent behind all three. The split is purely about who is allowed to call.

There are three front doors, each with its own authentication. AWS principals use IAM SigV4 directly. Other agents use the open A2A protocol over JSON-RPC, authenticated with OAuth tokens from Cognito or Microsoft Entra. And there's an optional human web UI — currently switched off to save money, but ready to turn back on. Same agent behind all of them; the only difference is who's allowed to call.

Agent-to-agent ingress

Non-blocking, so long assessments don't time out

Agent caller→ API Gateway
JWT authorizer→ Bridge Lambda
submit only→ SQS + DLQ→ Worker Lambda
runs the turn

message/send returns a submitted task in under a second; a worker runs the agent out of band and the caller polls tasks/get until it's done.

The agent-to-agent path is deliberately non-blocking. API Gateway caps a request at thirty seconds, but a full gap analysis takes longer. So message-send writes a task and returns immediately; an SQS-triggered worker Lambda runs the agent turn out of band, with a dead-letter queue if it fails; the caller polls for the result. Long assessments no longer time out, and a failed task can't infinitely retry.

Security

Built for non-human identities

  • Bedrock Guardrail on every model call — prompt-attack, PII, and harmful-content filtering.
  • OAuth2 client-credentials with a narrow invoke scope and 60-minute tokens.
  • Caller isolation — session IDs are derived per caller, so no two agents share context.
  • Aligned to the OWASP Non-Human Identities Top 10 — least privilege, short-lived secrets, no credential reuse.
Because the callers are machines, security is built around non-human identities. Every model call passes through a Bedrock Guardrail. Machine callers authenticate with OAuth client-credentials, scoped to just "invoke," with sixty-minute tokens. Sessions are isolated per caller. And the whole design is mapped against the OWASP Non-Human Identities Top 10 — least privilege, short-lived secrets, no shared credentials.

Cost engineering

From standing cost to pay-per-use

Before

  • Fargate + ALB + CloudFront running 24/7 for a human UI
  • ~$30–40/month standing cost even when idle
  • No guard on runaway agent traffic

After (agents-only)

  • Human UI disabled — one Terraform flag
  • Core agent is pay-per-use: ~$0 when idle
  • Per-route API throttling + a monthly budget alarm
When the project went agents-only, we cut cost deliberately. The human web UI — Fargate, a load balancer, and CloudFront — ran around the clock and cost thirty to forty dollars a month even idle. Disabling it is one Terraform flag. The core agent is pay-per-use, basically free when nothing's calling it. And we added per-route throttling and a monthly budget alarm so machine traffic can't run up a surprise bill.

The data stays current on its own. A weekly EventBridge job runs a Lambda that checks the published SCF version. If there's a new release, it uploads the data, re-indexes the knowledge base, reloads DynamoDB, and emails the team. Nobody has to babysit framework updates.
